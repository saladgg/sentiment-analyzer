# Data model

This document describes every record shape that crosses a layer boundary —
the API, the engines, RAG, and persistence. The authoritative source is
[`api/schemas.py`](../sentiment_analyzer/api/schemas.py); shapes that are not
formal Pydantic models are documented inline here.

## API contract

### `AnalysisRequest`

```python
class AnalysisRequest(BaseModel):
    data: Any                       # list[dict] | str
    source_type: str                # "json" | "csv" | "excel" | "text"
    sentiment_engine: str = "rule_based"
```

`data` is `Any` because adapters take care of validation. For programmatic
clients hitting `POST /api/analyze`, pass a list of dicts.

### `RecordSentiment`

```python
class RecordSentiment(BaseModel):
    record_id: int
    sentiment: str                       # "positive" | "neutral" | "negative"
    score: float                         # in [-1.0, 1.0]
    contributing_fields: dict[str, float]  # engine-specific drivers
```

`record_id` is the index in the input list. `contributing_fields` mirrors the
`drivers` returned by the chosen engine — see [engines.md](engines.md).

### `RAGMetadata`

```python
class RAGMetadata(BaseModel):
    enabled: bool
    used: bool
    source_count: int = 0
```

- `enabled` — mirrors `ASA_RAG_ENABLED`.
- `used` — `true` if at least one record received non-empty context.
- `source_count` — total unique sources matched across all records (sums the
  `len(rag_result.sources)` for each enriched record).

### `AnalysisResponse`

```python
class AnalysisResponse(BaseModel):
    run_id: str
    summary: dict
    records: list[RecordSentiment]
    anomalies: list[dict]
    explanations: list[str]
    rag: RAGMetadata | None = None
```

`summary` is intentionally typed as `dict` to keep aggregation flexible. It
currently has the shape:

```json
{
  "total_records": 10,
  "distribution": { "positive": 6, "negative": 3, "neutral": 1 },
  "dominant_sentiment": "positive"
}
```

See [`analytics/aggregation.py`](../sentiment_analyzer/analytics/aggregation.py).

`anomalies` reuses the per-record schema — items are full record dicts whose
score lies more than 2σ from the mean (see
[`analytics/anomalies.py`](../sentiment_analyzer/analytics/anomalies.py)).

`explanations` is a parallel list of human-readable strings, one per record,
generated by
[`analytics/explainability.py`](../sentiment_analyzer/analytics/explainability.py).

### Internal per-record record (extended)

The payload `AnalysisService` builds for each record (before being passed
through the `RecordSentiment` filter) is:

```python
{
    "record_id": int,
    "sentiment": str,
    "score": float,
    "contributing_fields": dict[str, float],
    "rag": {
        "enabled": bool,
        "sources": list[str],
        "chunks_used": int,
    },
}
```

`RecordSentiment` strips the `rag` block when serializing the API response —
RAG metadata is summarized at the response top level via `RAGMetadata`.

## Engine contract

Every `SentimentEngine.analyze` returns:

```python
{
    "label":   "positive" | "neutral" | "negative",
    "score":   float,                # in [-1.0, 1.0]
    "drivers": dict[str, float],     # engine-specific
}
```

See [engines.md](engines.md) for engine-specific `drivers` semantics.

## RAG types

```python
@dataclass
class RAGChunk:
    content: str
    source: str
    score: float        # 1 - distance, higher = more similar

@dataclass
class RAGResult:
    enabled: bool
    context: str        # "\n".join(chunks)
    sources: list[str]  # unique source labels
    chunks: list[RAGChunk]
```

Defined in [`rag/models.py`](../sentiment_analyzer/rag/models.py). Note: there
is a second `RAGResult` in
[`rag/types.py`](../sentiment_analyzer/rag/types.py) used by older paths;
prefer `models.RAGResult` for new code.

## Vector store records

Each chunk stored in Chroma (via
[`rag/vector_store.py`](../sentiment_analyzer/rag/vector_store.py)) has the
metadata:

```python
{
    "document_id": str,    # parent document UUID
    "namespace":   str,    # default "" if not provided
    "source":      str,    # filename / URL / label
    "chunk_index": int,
}
```

The chunk id has the form `{document_id}:{chunk_index}` so document deletion
removes every chunk in one query.

## Run persistence

DuckDB schema (created by
[`RunStore._init_schema`](../sentiment_analyzer/storage/runs.py)):

```sql
CREATE TABLE IF NOT EXISTS runs (
    run_id      TEXT PRIMARY KEY,
    engine      TEXT,
    summary     JSON,
    rag_enabled BOOLEAN,
    created_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

Notes:

- Only the run-level summary is stored, not the per-record records — those
  are returned synchronously and not persisted.
- `summary` is the same dict described under `AnalysisResponse.summary`.
- `created_at` is set by DuckDB. The DB file path is `ASA_RAG_DB_PATH`
  (default `runs.duckdb`).

## Field-detection heuristic

Text fields are auto-detected by
[`processing/field_detector.py`](../sentiment_analyzer/processing/field_detector.py):

> A field is text-bearing if its first-record value is a string longer than
> 10 characters.

This is intentionally minimal. To override the heuristic for specific
schemas, you would pre-flatten or rename your input fields before calling
the API, or extend `detect_text_fields` to accept hints.
